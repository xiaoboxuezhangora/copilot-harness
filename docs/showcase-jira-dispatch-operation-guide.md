# AI 开发中枢 · Jira 调度与治理驾驶舱操作说明

版本：v0.1  
日期：2026-05-16  
适用前端：`apps/showcase`  
适用用户：研发主管、项目经理、产品负责人、AI 交付平台管理员  
关联设计文档：`docs/showcase-jira-dispatch-skill-assignment-design.md`

## 1. 文档目的

本文档用于说明当前前端页面「Jira 调度与治理驾驶舱」的主要功能、操作入口、推荐使用流程和注意事项。

该页面面向研发主管的日常 AI 交付调度场景，核心目标是把真实 Jira 队列转化为可治理、可追踪、可审计的 AI 执行链路：

- 从 Jira 筛选任务。
- 识别高优先级、待确认、处理中、提交测试等状态。
- 为 Jira 分配 Skill 与 Agent 执行链路。
- 在触发前检查 MCP 权限、预算、写入风险和人工确认点。
- 跟踪 Agent 执行、MR Review、证据链和审计日志。
- 使用策略思考助手快速理解当前任务和瓶颈。

## 2. 启动与访问

### 2.1 本地启动

在项目根目录执行：

```bash
pnpm --filter @copilot-harness/showcase dev -- --host 127.0.0.1
```

当前本地访问地址：

```text
http://localhost:5173/
```

如果端口被占用，Vite 会提示新的本地地址，以终端输出为准。

### 2.2 推荐浏览器状态

- 推荐使用桌面宽屏浏览器查看。
- 页面支持浅蓝白天模式和夜晚模式。
- 页面部分操作会写入浏览器本地状态，例如主题偏好、当前页面内的编排状态和审计记录。

## 3. 当前版本行为边界

当前页面是 Showcase 前端界面，主要用于调度链路演示和操作验证。

需要特别注意：

- 「刷新」会更新页面时间并记录一次只读刷新审计，不会直接改写 Jira。
- 「同步并触发」会在当前前端状态中执行校验/触发流程演示。
- 「下载证据包」会在浏览器本地下载 JSON 文件。
- 「复制证据链接」会把当前证据锚点写入剪贴板。
- 「打开 Jira」会打开配置的 Jira 浏览地址。
- 「打开 MR」会打开当前数据中关联的 MR 地址。
- 高危任务会先进入「等待人工确认」，需要主管确认后才进入执行态。

## 4. 页面整体布局

页面采用「左侧全局导航 + 顶部控制条 + KPI 概览 + 左侧筛选器 + 中央任务队列 + 中央流水线 + 右侧详情抽屉 + 底部审计日志 + 右下策略助手」结构。

| 区域 | 名称 | 用途 |
| --- | --- | --- |
| 左侧窄栏 | 全局导航 | 展示系统模块入口和当前用户信息 |
| 顶部 | 调度控制条 | 切换项目、目标版本、Jira 筛选器、主题、刷新与触发 |
| 顶部卡片 | KPI 总览 | 查看 Jira 总数、待处理、处理中、提交测试、高优先级等统计 |
| 左侧面板 | Jira 筛选器 | 按项目、类型、状态、负责人、版本、模块、优先级、标签等筛选 |
| 中央上部 | Jira Issue Queue | 查看 Jira 列表、选择任务、分配 Skill、批量处理 |
| 中央下部 | Active Pipeline | 按交付阶段查看任务流转状态 |
| 右侧抽屉 | Jira 详情与 Skill 编排 | 查看详情、编排 Skill、查看步骤、证据链和 MR |
| 底部 | Execution History / 审计日志 | 查看最近调度记录、Trace 和产物入口 |
| 右下角 | 策略思考助手 | 围绕当前 Jira 提问、获取 Skill 建议和瓶颈分析 |

## 5. 左侧全局导航

当前只有「Jira 调度」模块已开发为完整页面。其他入口用于展示未来信息架构，页面会显示「暂未开发」标识。

点击未开发入口时，主内容顶部会显示模块说明：

| 入口 | 当前状态 |
| --- | --- |
| 仪表盘 | 暂未开发，总览看板与跨项目趋势尚未接入 |
| 工作流 | 暂未开发，流程模板与审批流尚未接入 |
| Skill 管理 | 暂未开发，独立 Skill 库和版本管理尚未接入；当前可在 Jira 详情抽屉内编排 Skill |
| Agent 状态 | 暂未开发，独立监控页尚未接入；当前可在执行步骤页签查看 Agent 状态 |

## 6. 顶部控制条操作

### 6.1 项目选择

入口：顶部「项目」下拉框。

用途：

- 切换当前调度项目。
- 联动 Jira 队列、KPI、Pipeline 和 JQL 预览。

当前示例项目为「新手麻 (APMIS)」。

### 6.2 目标版本选择

入口：顶部「目标版本」下拉框。

用途：

- 按目标版本筛选 Jira。
- 与左侧筛选器中的 `目标版本 cf[13301]` 保持同一筛选语义。
- 会影响中央队列和 KPI 命中数。

### 6.3 Jira 筛选器选择

入口：顶部「Jira 筛选器」下拉框。

当前预置项：

- `主版本jira列表 (86004)`

选择后会套用保存筛选器对应的 JQL 条件。

### 6.4 自动执行开关

入口：顶部「自动执行：ON/OFF」。

用途：

- 表示当前调度策略是否允许自动执行。
- 当前 Showcase 版本中，该开关主要用于展示执行策略状态；实际触发仍以「校验并触发」或「同步并触发」为准。

推荐使用方式：

- 日常演示和高危任务处理时保持 OFF。
- 展示低风险任务自动化策略时再切换为 ON。

### 6.5 白天/夜晚模式

入口：顶部「白天 / 夜晚」按钮。

行为：

- 点击「白天」切换到夜晚模式。
- 点击「夜晚」切换到白天模式。
- 页面会记住浏览器本地的主题偏好。
- 无本地偏好时默认使用白天浅蓝主题。

使用建议：

- 白天模式适合演示和会议投屏。
- 夜晚模式适合长时间监控和低亮环境。

### 6.6 日历与今日安排

入口：顶部时间卡片。

点击后显示：

- 当前月份日历。
- 今日安排，例如高危 Jira 拍板、MR Review 窗口。

### 6.7 刷新

入口：顶部「刷新」按钮。

行为：

- 更新当前页面时间。
- 在底部审计日志中新增「只读刷新」记录。

使用场景：

- 演示只读同步链路。
- 在处理前确认页面状态。

### 6.8 同步并触发

入口：顶部「同步并触发」按钮。

行为：

- 先更新页面时间。
- 对当前选中的 Jira 执行与「校验并触发」一致的流程。
- 非高危任务进入「Agent 执行中」。
- 高危任务进入「等待人工确认」。

## 7. KPI 总览

顶部 KPI 卡片用于快速判断当前 Jira 队列健康度。

| KPI | 含义 | 使用建议 |
| --- | --- | --- |
| Jira 总数 | 当前 JQL 或筛选范围内的 Jira 总量 | 判断当前队列规模 |
| 待确认/待处理 | Jira 状态属于待确认或待处理的数量 | 优先进入人工判断 |
| 处理中 | 当前处于处理中/进行中的数量 | 查看正在推进的任务 |
| 提交测试 | 开发完成或测试中的数量 | 关注测试和回归验证 |
| 高优先级 | 优先级高、加急、P0/P1 等任务数量 | 主管应优先检查 |

KPI 会随左侧筛选条件变化而联动更新。

## 8. 左侧 Jira 筛选器

左侧筛选器用于定位 Jira 队列。

### 7.1 展开与收起

入口：筛选器面板右上角「收起 / 展开」。

行为：

- 点击「收起」压缩左侧筛选区域，给中央队列和流水线更多空间。
- 点击「展开」恢复完整筛选器。

### 7.2 重置筛选

入口：筛选器面板右上角「重置」。

行为：

- 清空搜索文本。
- 恢复默认项目、版本、类型、状态、负责人、优先级、标签等条件。
- 切回「筛选器生成」JQL 模式。
- 清除已应用 JQL 提示。

### 7.3 常用筛选字段

| 字段 | 说明 |
| --- | --- |
| 项目 | 当前 Jira 项目，例如 APMIS |
| 类型 | 缺陷、需求等 Issue 类型 |
| 状态 | Jira 原始状态，例如处理中、待处理、提交测试、已关闭 |
| 经办人 | 全部用户、当前用户、指定用户 |
| 指定经办人 | 仅在经办人选择「指定用户」时显示 |
| 包含文本 | 支持 Jira Key、标题、描述、负责人等文本搜索 |
| 目标版本 cf[13301] | 按目标版本筛选 |
| 影响版本 | 按影响版本筛选 |
| 产品线和模块 cf[10126] | 按业务模块筛选 |
| 缺陷分类 cf[10302] | 按缺陷分类筛选 |
| 问题分类 cf[10116] | 按问题分类筛选 |
| 项目来源 cf[10121] | 按项目来源筛选 |
| 核心回收分析 cf[12400] | 按核心回收分析状态筛选 |
| 关联需求是否释放 cf[15603] | 按需求释放状态筛选 |
| 优先级 | 按低、中、高、加急等优先级筛选 |
| 标签 | 按 Jira labels 筛选 |
| 排序 | 按更新时间、目标版本、优先级、创建时间排序 |

### 7.4 保存的筛选器

当前页面提供以下快捷筛选：

| 筛选器 | 用途 |
| --- | --- |
| 主版本 Jira 列表 | 恢复主版本默认筛选条件 |
| 我的待确认 | 聚焦当前选中负责人且等待人工确认的任务 |
| 高危待处理 | 聚焦高优先级且等待人工确认的任务 |
| 未分配 Skill | 聚焦仍处于待编排的任务 |
| MR 待评审 | 聚焦等待代码评审的任务 |
| 高优先级 | 聚焦高、加急、P0/P1 等优先级任务 |
| Angular17 相关 | 聚焦标题或描述包含 Angular17 的前端升级回归任务 |

### 7.5 JQL 模式

JQL 区域提供两种模式：

| 模式 | 用途 |
| --- | --- |
| 筛选器生成 | 根据左侧筛选条件自动生成 JQL |
| 手动输入 JQL | 手动编辑完整 JQL |

操作步骤：

1. 选择筛选条件。
2. 保持「筛选器生成」或切换到「手动输入 JQL」。
3. 点击「搜索」。
4. 页面显示已应用的 JQL 提示。

注意：

- 当前 Showcase 中搜索主要更新前端状态提示。
- 接入扩展 MCP 后，可由 JiraReader 执行真实搜索。

## 9. Jira Issue Queue 操作

中央上方的 Jira Issue Queue 是主操作区。

### 8.1 列说明

| 列 | 说明 |
| --- | --- |
| 选 | 勾选后进入批量操作 |
| Key | Jira 编号，单击选中，双击打开 Jira 原始页面 |
| Summary | Jira 标题和部分标签 |
| 模块 | 所属业务模块 |
| 优先级 | 低、中、高、加急等 |
| 负责人 | 当前经办人 |
| 调度状态 | AI 编排状态 |
| Skill | 已分配 Skill 数量，未分配时显示「未分配」 |
| 操作 | 点击「分配 Skill」进入右侧 Skill 编排 |

### 8.2 选中 Jira

操作：

1. 在队列中点击 Jira Key 或 Summary。
2. 页面右侧打开详情抽屉。
3. 默认进入「概览」页签。

结果：

- 当前 Jira 高亮。
- 右侧显示该 Jira 的状态、摘要、风险、负责人和后续操作。

### 8.3 打开 Jira 原始页面

操作：

1. 在队列中双击 Jira Key。
2. 或在右侧「概览」页签点击「打开 Jira」。

结果：

- 浏览器新窗口打开 Jira 原始地址。

### 8.4 单条分配 Skill

操作：

1. 在目标 Jira 行点击「分配 Skill」。
2. 右侧抽屉切换到「Skill 编排」页签。
3. 勾选或取消 Skill。
4. 使用「上移 / 下移」调整执行顺序。
5. 查看触发前校验。
6. 根据目标点击「仅保存草稿」「保存编排」或「校验并触发」。

### 8.5 批量选择 Jira

操作：

1. 勾选多条 Jira 左侧复选框。
2. 队列上方出现批量操作条。

可用操作：

| 操作 | 行为 |
| --- | --- |
| 套用标准链路 | 为选中 Jira 套用推荐 Skill 模板，并保存为草稿 |
| 批量进入校验 | 普通任务进入 Skill 已分配，高危任务进入等待人工确认 |
| 取消选择 | 清空当前勾选项 |

如果未勾选任何 Jira，顶部「批量套用模板」会作用于当前选中 Jira。

## 10. Active Pipeline 操作

Active Pipeline 用于查看 AI 交付流转阶段。

### 9.1 流水线列

| 列 | 含义 |
| --- | --- |
| 待理解 | 尚未完成需求理解或未进入编排 |
| Skill 已分配 | 已完成 Skill 编排，等待触发 |

### 9.2 任务卡片

每张卡片展示：

- Jira Key。
- Summary。
- 当前 Agent。
- 预计或已用耗时。
- 已绑定 Skill 标签。

点击任务卡片会选中对应 Jira，并打开右侧详情抽屉。

### 9.3 按流水线阶段筛选

操作：

1. 点击某个流水线列头右侧的数量按钮。
2. 页面将中央队列筛选到该调度状态。

适用场景：

- 快速查看正在执行的任务。
- 聚焦 MR 待 Review。
- 查找等待人工确认的任务。

右侧抽屉是单个 Jira 的操作中心。

打开方式：

- 点击 Pipeline 任务卡。
- 点击审计日志中的「查看」。
- 点击策略助手建议关联的任务入口。

关闭方式：

- 点击抽屉右上角「×」。

### 10.2 概览页签

显示内容：

- 风险等级。
- Jira 状态。
- 经办人。
- 优先级。
- Jira 描述摘要。
- 原文脱敏展示。
- 今日人工确认事项。

可用操作：

| 操作 | 行为 |
| --- | --- |
| 打开 Jira | 新窗口打开 Jira 原始页面 |
| 查看原文 / 收起原文 | 展开或收起脱敏后的原始描述 |

高危任务会显示「高危写操作确认」卡片。点击「主管确认并进入执行」后，任务进入「Agent 执行中」，并新增审计记录。

### 10.3 Skill 编排页签

该页签用于决定当前 Jira 应由哪些 Skill 和 Agent 处理。

#### 推荐 Skill 列表

当前可选 Skill：

| Skill | Agent | MCP/能力 | 输入 | 说明 |
| --- | --- | --- | --- | --- |
| 需求澄清 | PM Agent | JiraReader | Jira 描述/评论 | 推荐且通常必选 |
| 影响面分析 | Impact Analyst | CodeRetrieval | Jira + 模块标签 | 推荐且通常必选 |
| 代码检索 | Code Searcher | GitLabReader | GitLab 仓库 | 用于定位代码影响面 |
| 方案生成 | Solution Architect | Planner | 需求 + 影响面 | 生成实施方案，需人工确认 |
| 测试用例生成 | QA Agent | TestCaseMCP | 方案文档 | 生成测试用例，受预算约束 |
| MR Review | Reviewer Agent | GitLabMR | MR Diff | 写入或评审相关操作需确认 |
| 安全扫描 | Security Scanner | PolicyMCP | 代码变更 | 高危场景需确认 |
| Angular17 升级回归分析 | Angular Expert | CodeRetrieval + GitLabReader | Angular17 Jira + odcbs-frontend | 专项处理 Angular17 升级后的空白页、图标色差、布局变形等前端回归 |

#### 业务 Skill 匹配

当 Jira 标题或描述包含 `Angular17` 时，Skill 编排页会显示「业务 Skill 匹配」卡片。

卡片会展示：

- 命中的业务 Skill：`Angular17 升级回归`。
- 匹配置信度：例如高置信。
- 推荐代码库：`apmis/odcbs/odcbs-frontend`。
- 推荐分支：`develop_to_angular17`。
- 匹配信号：例如标题/描述包含 Angular17、图标或样式漂移、空白页或加载异常。
- 代码分析重点：升级回归范围、共享组件、历史 MR、可验证修复建议。

点击「应用 Angular17 Skill」后，会把当前 Jira 的 Skill 顺序整理为：

1. 需求澄清。
2. 影响面分析。
3. Angular17 升级回归分析。
4. 代码检索。
5. 方案生成。
6. 其他已选择 Skill。

点击成功后，按钮会变为「已应用 Angular17 Skill」，并显示已写入当前 Jira Skill 编排、已保存为草稿的状态提示。

#### Jira 结合代码生成开发方案

一个 Jira 进入代码分析并形成开发方案的标准链路为：

1. 读取 Jira 上下文：标题、描述、状态、优先级、目标版本、模块、负责人和标签。
2. 匹配业务 Skill：根据 Angular17、升级后、空白页、图标色差、布局变形等信号选择专项 Skill。
3. 定位代码范围：Angular17 工单固定映射到 `apmis/odcbs/odcbs-frontend` 的 `develop_to_angular17` 分支。
4. 执行代码分析：检索相关组件、路由、样式、历史 MR、共享模块和可能的影响面。
5. 输出开发方案：给出修改点、风险、验证命令、回归用例和人工确认事项。

## 14. 推荐操作流程

### 13.1 每日调度巡检

1. 打开页面。
2. 确认项目和目标版本。
3. 查看 KPI：重点关注「待确认/待处理」和「高优先级」。
4. 点击保存筛选器「高优先级」或「我的待确认」。
5. 在 Jira Issue Queue 中逐条查看高风险任务。
6. 对需要 AI 处理的任务点击「分配 Skill」。
7. 保存编排或进入触发前校验。
8. 打开审计日志确认操作被记录。

### 13.2 单个 Jira 编排并触发

1. 在队列中点击目标 Jira。
2. 在右侧概览页查看摘要、负责人、状态和风险。
3. 点击「分配 Skill」。
4. 在 Skill 编排页勾选需要的 Skill。
5. 调整 Skill 顺序。
6. 查看触发前校验。
7. 点击「保存编排」。
8. 若确认可执行，点击「校验并触发」。
9. 普通任务进入「Agent 执行中」。
10. 高危任务进入「等待人工确认」，需要主管确认后再执行。

### 13.3 批量套用标准链路

1. 在 Jira Issue Queue 勾选多条 Jira。
2. 点击批量操作条中的「套用标准链路」。
3. 页面为选中任务套用推荐 Skill 模板。
4. 确认无误后点击「批量进入校验」。
5. 高危任务会进入「等待人工确认」，普通任务进入「Skill 已分配」。

### 13.4 处理高危任务

1. 使用「高危待处理」或「高优先级」筛选器定位任务。
2. 点击目标 Jira 打开概览。
3. 查看「高危写操作确认」卡片。
4. 检查描述摘要、影响范围、证据链和 MR 信息。
5. 确认可执行后点击「主管确认并进入执行」。
6. 在审计日志中确认新增记录。

### 13.5 查看证据链并导出

1. 选中目标 Jira。
2. 打开右侧「证据链」页签。
3. 点击「查看 MCP 调用」确认调用权限和 trace 状态。
4. 点击「下载证据包」导出 JSON。
5. 如需共享页面位置，点击「复制证据链接」。

### 13.6 跟踪 MR Review

1. 在保存筛选器中点击「MR 待评审」，或在 Pipeline 点击「MR 待 Review」列数量。
2. 选中目标 Jira。
3. 打开右侧「MR」页签。
4. 查看关联 MR、影响仓库和模块。
5. 点击「打开 MR」进入 GitLab。
6. 如需推进状态，点击「发起 Review」。
7. 如需主管介入，点击「标记需人工确认」。

### 13.7 使用策略助手辅助判断

1. 选中一个 Jira。
2. 点击右下角小牛按钮。
3. 点击「这个 Jira 应该分配哪些 Skill？」。
4. 根据助手建议检查 Skill 编排。
5. 如需定位风险，继续提问「哪些任务需要主管先确认？」。

## 15. 调度状态说明

| 状态 | 含义 | 典型入口 |
| --- | --- | --- |
| 待编排 | 尚未分配 Skill | 初始状态或未分配 Skill 筛选 |
| 草稿 | 已套用模板或保存草稿，但未完成编排确认 | 应用模板、仅保存草稿 |
| Skill 已分配 | 已保存 Skill 编排，等待触发 | 保存编排、批量进入校验 |
| Agent 执行中 | 已通过校验并进入执行 | 校验并触发、同步并触发、主管确认 |
| MR 待 Review | 进入代码评审阶段 | MR 页签「发起 Review」 |
| 等待人工确认 | 高危、写操作或关键决策等待确认 | 高危任务触发、标记需人工确认 |
| 已完成 | 任务已完成 | 审计或快照状态 |
| 失败 | 执行失败，需要人工介入 | 审计或快照状态 |

## 16. 常见问题

### 15.1 为什么点击搜索后没有真实请求 Jira？

当前页面是 Showcase 前端，搜索会更新前端状态和 JQL 提示。接入扩展 MCP 后，搜索可由 JiraReader 提交到真实 Jira。

### 15.2 为什么高危任务点击校验并触发后没有直接执行？

高危任务会先进入「等待人工确认」。这是治理规则要求，需在概览页点击「主管确认并进入执行」后才进入执行态。

### 15.3 主题为什么保持上次选择？

主题偏好写入浏览器本地存储。清理浏览器站点数据后会恢复默认白天模式。

### 15.4 下载的证据包包含什么？

证据包是 JSON 文件，包含当前 Jira Key、Summary、MCP 调用、证据列表和 reasoning。

### 15.5 审计日志为什么出现新记录？

刷新、保存草稿、保存编排、校验触发、复制证据链接、主管确认等操作都会追加审计记录，便于演示可追溯链路。

### 15.6 自动执行开关打开后为什么仍要点击触发？

当前版本中自动执行开关主要展示策略状态。实际状态推进仍由「校验并触发」或「同步并触发」驱动。

## 17. 演示建议

对外演示时建议按以下顺序：

1. 切换到白天模式，展示浅蓝主题驾驶舱。
2. 从 KPI 说明当前队列规模和风险。
3. 使用「高优先级」或「我的待确认」筛选任务。
4. 选择一个 Jira，打开右侧概览。
5. 进入 Skill 编排，展示推荐 Skill、Agent、MCP、预算和校验。
6. 点击「保存编排」或「校验并触发」。
7. 展示 Pipeline 状态变化。
8. 打开证据链，下载证据包。
9. 展开审计日志，说明每次操作都可追踪。
10. 打开策略助手，提问当前 Jira 应分配哪些 Skill。

## 18. 运维与排障提示

| 现象 | 处理 |
| --- | --- |
| 页面打不开 | 确认 Vite 服务是否启动，检查终端实际端口 |
| 筛选后队列为空 | 点击「重置」，或检查项目/版本/状态组合是否过窄 |
| 手动 JQL 不符合预期 | 切回「筛选器生成」，重新由筛选条件生成 |
| 右侧抽屉不见了 | 点击队列行、Pipeline 卡片或「分配 Skill」重新打开 |
| 复制证据链接失败 | 检查浏览器剪贴板权限 |
| 打开 Jira/MR 失败 | 检查内网地址、GitLab/Jira 登录状态和网络权限 |
| 页面状态混乱 | 刷新浏览器页面，必要时清理站点本地存储 |
